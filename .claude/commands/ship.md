Drive pull request $ARGUMENTS (without a number: the current branch's) to its merge.

0. With a number, work on that PR's branch, never on `main` or another PR's branch: in the worktree that has it checked out, or check it out with `gh pr checkout` and the number in a clean worktree of its own.
1. `/done` step 7b in full: sync with `main`, `/ponytail-review`, status bump, push.
2. Wait for CI first, one blocking wait in the background: `gh pr checks` with the PR's number written out, then `--watch --fail-fast`. Right after a push it can exit with "no checks reported" before GitHub has registered the runs: wait a minute and start it again, up to five times. Any other non-zero exit means a check failed: read its log (`gh run view` with the run id from the check's link, then `--log-failed`) and fix it before anything else, never go on waiting for the review. Then wait once for Codex, in the background: `python3 scripts/codex_review.py` with the PR's number and `--wait`. It exits 0 clean, 1 findings (listed with their comment ids), 3 stalled. Codex reviews every push by itself within seconds and is done in 4 to 8 minutes, so `@codex review` after a push only duplicates it. A run can hang silently: on #371 two did, both with thread replies posted within seconds of the push, so answer review threads before the push, not after it. Only "stalled" (running for more than 15 minutes, or no review of the head started within 15 minutes) gets one comment `@codex review`, never a second.
3. Fix rounds follow `CLAUDE.md` §6 "Reviews" and "Review loop limits": check each finding against the code, fix a confirmed one with a test, answer a wrong or outdated one on its thread with the evidence, push all fixes of the round at once, then wait again (step 2). An unfixed P2 gets no reply of its own; it goes into the `Merge gate:` comment. Merge `main` only when step 4 needs it, never during fix rounds: after every merge from `main`, the review is due again too.
4. Merge per `CLAUDE.md` §6 "Merging a PR into `main`". A PR with an `xhigh` trigger is reported ready and stays with Maxi. Otherwise run the one form the hook takes, with the PR's number and the full 40-character head sha written out (no placeholders, no shell variables): `gh pr merge`, the number, `--merge`, `--match-head-commit`, the sha. Then: never `--auto`, no wrapper around it, and no other command that names it (a commit message that names it goes into a file, passed with `git commit -F` and the file's path). The project hook `.claude/hooks/merge_gate.sh` blocks it while a check, the sync with `main`, the bump or a clean review on that head is missing, and its message says what to do.
5. `/done` step 8: tidy up.
