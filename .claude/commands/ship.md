Drive pull request $ARGUMENTS (without a number: the current branch's) to its merge.

1. `/done` step 7b in full: sync with `main`, `/ponytail-review`, status bump, push.
2. Wait for CI first, one blocking wait in the background: `gh pr checks` with the PR's number written out, then `--watch --fail-fast`. Right after a push it can exit with "no checks reported" before GitHub has registered the runs: wait a minute and start it again, up to five times. Any other non-zero exit means a check failed: read its log (`gh run view` with the run id from the check's link, then `--log-failed`) and fix it before anything else, never go on waiting for the review. Then wait once for the Codex state comment that names the head (`codex-review-state` with that `commit_sha` and `"status":"completed"`), and also stop when Codex posts a review on that head. A push that got no review after 15 minutes gets one comment `@codex review`.
3. Fix rounds follow `CLAUDE.md` §6 "Reviews" and "Review loop limits": check each finding against the code, fix a confirmed one with a test, answer the rest on their thread, push, then wait again (step 2). After every merge from `main`, the review is due again too.
4. Merge per `CLAUDE.md` §6 "Merging a PR into `main`". A PR with an `xhigh` trigger is reported ready and stays with Maxi. Otherwise run the one form the hook takes, with the PR's number and the full 40-character head sha written out (no placeholders, no shell variables): `gh pr merge`, the number, `--merge`, `--match-head-commit`, the sha. Then: never `--auto`, no wrapper around it, and no other command that names it (a commit message that names it goes into a file, passed with `git commit -F` and the file's path). The project hook `.claude/hooks/merge_gate.sh` blocks it while a check, the sync with `main`, the bump or a clean review on that head is missing, and its message says what to do.
5. `/done` step 8: tidy up.
