Drive pull request $ARGUMENTS (without a number: the current branch's) to its merge.

1. `/done` step 7b in full: sync with `main`, `/ponytail-review`, status bump, push.
2. Wait for CI first, one blocking wait in the background: `gh pr checks <n> --watch --fail-fast`. A non-zero exit means a check failed: read its log (`gh run view <run> --log-failed`) and fix it before anything else, never go on waiting for the review. Then wait once for the Codex state comment that names the head (`codex-review-state` with that `commit_sha` and `"status":"completed"`), and also stop when Codex posts a review on that head. A push that got no review after 15 minutes gets one comment `@codex review`.
3. Fix rounds follow `CLAUDE.md` §6 "Reviews" and "Review loop limits": check each finding against the code, fix a confirmed one with a test, answer the rest on their thread, push, then wait again (step 2). After every merge from `main`, the review is due again too.
4. Merge per `CLAUDE.md` §6 "Merging a PR into `main`". A PR with an `xhigh` trigger is reported ready and stays with Maxi. Otherwise exactly `gh pr merge <n> --merge --match-head-commit <full head sha>`, the one form the hook takes: never `--auto`, no wrapper around it, and no other command that names it (a commit message goes through `git commit -F <file>`). The project hook `.claude/hooks/merge_gate.sh` blocks it while a check, the sync with `main`, the bump or a clean review on that head is missing, and its message says what to do.
5. `/done` step 8: tidy up.
