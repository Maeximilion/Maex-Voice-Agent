New customer

This page runs nothing. Every step is a command on the host, run by you over SSH; the dashboard only shows the new stack once it is registered.

1. The customer file

Copy deploy/customer.example.json and fill it in. The key names the stack everywhere: lower-case letters, digits and single hyphens, a letter first, at most {{ key_length }} characters. Not taken as a key: {% for word in reserved %}{{ word }}, {% endfor %}caddy.

2. The stack

On the server as the deploy user, from a checkout of the repository. First the check that writes nothing, then the run:

python3 scripts/new_stack.py customer.json --domain <domain> --dry-run

python3 scripts/new_stack.py customer.json --domain <domain>

The run prints the setup link of the restaurant's first sign-in once and stores it nowhere. It prints no secret. A second run keeps every token.

3. The menu and the self-test

Import the menu (docs/14), then run the stack's self-test:

python3 scripts/new_stack.py customer.json --domain <domain> --selftest

4. The registry of this dashboard

On the operator host, with the dashboard on the stack's ops network:

python -m api.dashboard.cli customer-add <key> http://<api container>:8000

The command asks for the stack's OPS_TOKEN (in the stack's .env) or reads it from standard input. Never give it as an argument: a command line is kept in the shell's history. The address is http://<host>:<port> and nothing else. customers lists the registry, customer-remove <key> takes a customer out.

5. The check

The customer stands in the list within 30 seconds. A row that says another customer answers at this address or refuses the token names what to correct with a second customer-add.
