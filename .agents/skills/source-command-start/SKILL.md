# source-command-start

Use this skill when the user asks to run the migrated source command `start`.

## Command Template

Session start for the Maex Voice Agent.

1. Sync: the project's SessionStart hook already fetched and fast-forwarded a clean `main`. Confirm with `git status -sb`. If a hook warning appeared (lock file, divergence, uncommitted changes on `main`), run step 2a first, then stop and report both: the warning is most often caused by exactly those leftovers. Never stash, reset or force.
2. Tidy up, only what is verifiably finished: a local branch whose remote is gone, or whose PR is merged with the same head SHA (check as in `/done` step 8), is deleted together with its worktree. Branches with unpushed commits, a PR closed without merge, or no PR stay; list each in one line. Never a `leftovers/*` branch, merged or not: step 2a reports it and Maxi decides. Touch nothing else.
2a. Leftovers, the reminder: report each of these in one line (a stash or a branch with its age, which its command prints), at every start until it is gone, and never stash, reset, delete or commit one yourself. (a) Uncommitted or untracked files in the folder that has `main` checked out, which block every pull of that folder: `main_dir=$(git for-each-ref --format='%(worktreepath)/' refs/heads/main); main_dir=${main_dir%/}; if [ -n "$main_dir" ]; then git -C "$main_dir" status --short --untracked-files=all; fi` (git names the folder itself, and lists untracked files whatever the Git setting for showing them says; the `/` behind it keeps a path that ends in a line break whole; no output and exit 0 without such a folder). (b) Stash entries: `git stash list --format='%gd %cr %s'`. (c) Local branches named `leftovers/*`: `git for-each-ref --format='%(refname:short) %(committerdate:relative) %(subject)' 'refs/heads/leftovers/*'`. For each one say what it holds and propose what to do with it (bring it into a PR, or delete it because its content is on `main`); the decision is Maxi's. With nothing found say nothing.
3. Read `AGENTS.md` in full.
4. Read `docs/01_STATUS.md` by section, not in full (it holds several hundred KB of history): the header (first 6 lines), `## Roadmap` through `## Open Decisions`, and `## Blockers`; take the line numbers from `grep -n '^## ' docs/01_STATUS.md`. Summary, assumptions, open points from reviews, Done and Changelog are read only when a task needs them. Of `docs/07_WORKPACKAGES.md` read only the open task rows: `grep -nE '^\| T-' docs/07_WORKPACKAGES.md | grep -vE '\| *(fertig|done|erledigt|dropped)[ ,:]'`; a `T-` dependency that is not in this list is finished; a decision (`D…`) or another prerequisite is checked in `## Open Decisions` and `## Blockers`.
5. Summarize in max 6 lines: current stage, next gate, open blockers, tasks with in-progress status.
5a. Security alerts: run `python3 scripts/alert_fixes.py`. It prints one line per open Dependabot and code-scanning alert, with the open PR into `main` that fixes it; what counts as a fix is in the script's header. No output and exit 0: no open alert, say nothing. Exit 1: an API call failed (for example a feature that is switched off); report each `error:` line in one line and never take a failed source for zero alerts. Otherwise add one line with the counts, the highest severity and the affected files. A line with `BLOCKS TASKS` is a Dependabot alert of any severity, or a critical or high code-scanning alert, that no open PR fixes (`CLAUDE.md` section 6 "Security alerts"): step 6 says first that the open alerts have to be fixed before any task, and suggests only their fix (one PR for all Dependabot alerts that the same pins close) and no other task, with the candidates the line names next to it, so a duplicate is never opened unseen. A line `fixed by #N`: name that PR, and step 6 goes on with tasks. A line `below high`: a code-scanning alert that is one of the suggestions in step 6.
6. Suggest 1–3 ready tasks (all dependencies done), mark one as recommendation and justify in one sentence. Name the model and effort from the "Model Routing" table in `CLAUDE.md` for each task. The table names Claude models, which a Codex session cannot switch to: state the routed model and effort as the recommendation for the Claude Code session that will run `/task`, and do not ask for a switch here. If a task's row carries the note `Environment: Ubuntu (WSL) on the workbench` and `grep -qi microsoft /proc/version` fails in this session, say that too: the task needs a session started in Ubuntu on Maxi's PC (docs/12_CLAUDE_CODE_PLAYBOOKS.md, S10).
7. Wait for your choice. Don't build yet.
