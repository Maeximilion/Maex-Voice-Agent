The dispatcher (`api/events/`) empties the outbox: its own process, one POST per event to n8n with event id as idempotency key, backoff 5 s / 30 s / 2 min / 10 min, then `failed` with alarm in log. Callbacks are also done: `create_callback` creates the task for the team, logs it, and reports it via outbox. `transfer_to_team` hands escalations to the team: always the extension from `service_config.team_phone`, never a main number, and runs at most once per call (state on `calls.transfer_reason`). The call log is done: `POST /v1/calls/start`/`/end` open and close the `calls` row the rest of Stage 1 depends on, and every `/v1/tools/*` call now lands in `calls.tool_calls` with duration and result, written generically by `core/tool_log.py` so no individual tool needed to change. `prompts/system_v1.md` and `tools_v1.md` are also done, scoped to the six tools that actually exist today.

`agent/` now exists (T-2.1, 17.09.2026): `prompt.py` loads `prompts/system_vN.md` and can append a menu index once one exists; `state.py` is the compact per-call state from docs/05 §5 (`stage`, `intent`, `slots`, `open`) instead of a growing transcript; `dispatch.py` is the direct, non-HTTP equivalent of `api/tools/*.py` — validates arguments, calls `domain/` straight (no HTTP detour, per docs/11 §agent), auto-derives `idempotency_key` for `create_reservation`/`confirm` so the model never has to (CLAUDE.md §2 rule 1), and writes every call into `calls.tool_calls` itself since the HTTP middleware never runs on this path; `loop.py` drives customer-turn → model → tool-calls → reply, aborting cleanly on `max_call_seconds` or a runaway tool loop; `llm.py` defines the swappable `LLMClient` interface plus a `FakeLLM` test double — a real model with token counting is T-2.4. **Codex review PR #101 (P1×3, P2×2) fixed same-day:** `LLMTurn` gained an optional `state_patch` so conversational details the model extracts (name, date, party size, ...) survive into the next compact state instead of vanishing the moment the turn ends; `state.to_prompt_json()` now exposes `reservation_id` once a draft exists, so a stateless model can still supply `entity_id` to `confirm` on the customer's "yes"; the loop rechecks `max_call_seconds` before every tool hop, not only once at turn start; a tool's `say` is now forwarded to the model instead of dropped, so it isn't left to invent wording for cases the code already has a prescribed sentence for; and — the one that mattered most — hitting `max_call_seconds` or the tool-hop limit no longer just *announces* a handoff to the team and hangs up: it now actually calls `transfer_to_team`, falling back to `create_callback` when a phone number is known and the team is unavailable, and only falling back further to the plain apology when neither is possible (CLAUDE.md §2 rule 5).

**T-2.2 done (17.09.2026):** `agent/ladder.py` is the understanding ladder as a small state machine (docs/05 §2) — per-field failure counts (`UnderstandingLadder`), one level-up after two failed attempts at the same information, and `should_end_call()` once three level-ups pass without success; stages 4 (keypad) and 5 (SMS) are context-specific tools per docs/05 §2, not mandatory rungs, so Stage 1's reservation fields (date, party size, name, phone) only ever climb through 1–3 before the ladder gives up on its own. `agent/escalation.py` is the immediate-trigger check from docs/05 §4 (complaint, human-requested, cancellation) — plain keyword matching on the raw customer text, run in `loop.py` before the model is ever called, so an obvious case costs no tokens. Both are wired into `loop.py`: `LLMTurn` gained `understanding_failure` (the field name that failed) so the model only has to report failures, never count them; a ladder hint (`{"field": level}`) rides along in the compact prompt state once a field is elevated; escalation runs first in every `run_turn()`, ahead of even the `max_call_seconds` check; and every loop-internal handoff (timeout, hop limit, ladder exhaustion, or a genuine escalation trigger) now goes through the same `_handoff()` from the T-2.1 Codex fix, just with the real reason threaded through instead of a hardcoded placeholder. **Codex review PR #102 (P2×3) fixed same-day:** a repeated `understanding_failure` for the same field within one `run_turn()` call (e.g. reported once on a tool-call hop and again on the final reply) now counts once, not once per hop, so the ladder can't climb faster than the customer actually failed; `escalation.py`'s cancellation trigger now matches the noun "Storno" itself (`"storn"`), not only the verb forms; and `_handoff()` now threads the triggering customer text into the `create_callback` summary, since a pre-model escalation never calls the LLM and would otherwise leave the team a fixed phrase with no record of what the customer actually wanted. Still open at that point: the GUI.

**T-2.3 done (17.09.2026): the through-cut without a phone runs.** `sim/` is the text phone: `python -m sim.cli` holds a call in the terminal, `python -m sim.replay <case>.json` replays a transcript in the format from docs/08 §1, and both write to the real database — a confirmed reservation is in `reservations` afterwards, without any voice platform. `sim/session.py` holds what both entry points share: `start_call` opens the `calls` row, the compact state runs through `agent/loop.py`, every tool call is shown with the duration that `calls.tool_calls` recorded, and `end_call` derives the outcome from the conversation state (`confirmed` to `completed`, `transferred`, `callback`, otherwise `abandoned`) instead of from what the model claims. `sim/noise.py` garbles input on purpose — letter swaps, cut-off and swallowed words — with a seed, so a failure of the understanding ladder is reproducible instead of anecdotal. Because a real model only arrives with T-2.4, `sim/scripted_llm.py` stands in for it: rule-based, scoped to the reservation flow of `prompts/system_v1.md` (status, collect, `check_slot`, `create_reservation`, read back, confirm on a clear yes). It recognizes party size, day and time, name and phone number; what it does not recognize it reports as a failed attempt to the ladder rather than guessing (CLAUDE.md §2 rule 2), and a failed tool without a prescribed sentence makes it really hand over instead of announcing it (rule 5). Measured on the first case (`evals/cases/reservierung_0001_tisch_fuer_vier.json`): four customer turns, tool calls between 7 and 15 ms, reservation `confirmed` in the database. **Codex review PR #104 (P1x4, P2x2) fixed same-day:** a yes is now matched at word boundaries, so "Im Januar muss ich erst nachsehen" no longer counts as the explicit yes that turns a draft into a booking (CLAUDE.md §2 rule 3); an out-of-scope request (menu, pickup, delivery, allergy) is checked before the status call and remembered until the callback exists, because the follow-up turn usually carries nothing but the phone number and would otherwise drop the caller back into the reservation questions; a reply naming only a new time ("dann halb acht" to an offered alternative) keeps the day already given instead of rebooking the evening onto today; an impossible spoken date ("am 31.02.") counts as not understood rather than being silently replaced by today, and no longer escapes the conversation loop as a ValueError; and `finish()` closes the call at the current time instead of the start time, so a conversation from the terminal no longer records zero seconds (`--now` still pins the clock for a reproducible replay); and a correction during the read-back ("Nein, wir sind fuenf Personen") now builds a new draft with a new read-back instead of leaving the old one in place, where a later yes would have confirmed the four-person draft the customer had just corrected. The corrected-away draft stays in the database as a draft and blocks capacity until the cleanup job for abandoned drafts exists (already listed as missing above). 46 new tests, 341 in total.

**T-0.8 done (17.09.2026):** `api/domain/menu/numberwords.py` turns spoken German numbers into integers, as a pure function without database or HTTP. The speech recognition delivers the same number in four shapes - as digits ("23"), as one word ("dreiundzwanzig"), written apart ("drei und zwanzig") or spoken digit by digit ("vierzig sieben") - and all four now yield the same value. Three entry points, because they differ at the phone: `parse_cardinal` (the whole text is the number), `find_item_number` (the number sits inside a sentence; an explicit "Nummer ..." beats everything, and two numbers without a marker give `None` instead of the first one) and `find_quantity` (only with a marker: zweimal, 2x, drei Portionen - a bare number is a dish, not an amount). No match gives `None`, never a guess (CLAUDE.md §2 rule 2); what follows from that - a question back, a rung of the understanding ladder, a handover - the caller decides. 375 tests: a round trip over 0 to 199 and every seventh value up to 999 against a separately written speller, plus the cases that actually go wrong on the phone. `sim/scripted_llm.py` now uses this module instead of its own provisional table, so "einundzwanzig Personen" works where twelve used to be the ceiling. Measured at 3 to 5 microseconds per call. 716 tests in total. **Codex review PR #105 (P1x2, P2x1) fixed in a follow-up, since the review arrived after the merge:** a number no longer grows across a punctuation mark or across the article of an amount, so "Nummer 20, eine Portion" is item 20 with one portion and no longer item 21 with amount 21 - the rule for digit-by-digit speech ("vierzig sieben") reached straight through the comma; an article that *begins* a number now counts, so "die ein und zwanzig" is 21 instead of 20, where the "ein" was discarded as an article before anyone checked whether it opens a number; and a number attached to an amount marker is no longer counted as a second dish number, so "2 x die 23" resolves instead of asking the guest back for nothing. Scanning now carries the position of each number (`_Span`), which is what makes the last one decidable at all. 8 new tests, 724 in total.

**T-4.3 done (18.09.2026): `search_menu`.** `POST /v1/tools/search_menu` resolves what the caller said to a `menu_item_id` in the order of docs/04: number, then exact alias, then trigram over name and aliases. One result above the high threshold is `fuzzy_single`; otherwise everything above the low threshold is `ambiguous` with at most three suggestions and a question in `say` ("Meinen Sie Nummer 47, Ente knusprig oder Nummer 48, Ente süß-sauer?"); nothing is `not_found`. Thresholds come from `MENU_FUZZY_THRESHOLD_HIGH`/`LOW` (0.72 / 0.45). Only active dishes are found; a sold-out dish comes back with `sold_out: true` and "… ist heute leider aus." Options are grouped, default first. `normalize_query` in `domain/menu/normalize.py` strips filler, number and quantity words; `numberwords.has_item_number_marker` is new. **Rule A (Maxi, 21.09.2026), after fifteen rounds of Codex findings on number parsing:** search_menu only takes a card number directly when the whole sentence is exactly that one number. Besides the number, a marker („Nummer“/„Nr.“), filler words, hesitations, punctuation and one quantity („zweimal die 23“, „zwei Nummer 23“) are allowed - nothing else. Anything mixed in - a second number, a name, an „oder“ - is `ambiguous` with one question: ‚Welche Nummer meinen Sie? Bitte sagen Sie mir nur die eine Nummer.‘ Without a marker, a number next to a name stays a quantity („zwei Frühlingsrollen“) and the name search decides. One rule instead of a growing list of special cases: every sentence shape that is not unambiguously a number becomes a question back rather than a silent wrong dish (CLAUDE.md §2 rule 2). `numberwords.sole_item_number` carries the rule; `find_item_number_ref`/`find_marked_item_numbers` remain for the ladder. Verification: pure tests (normalize, marker, numberwords) run locally, ruff clean; the DB and HTTP tests including p95 with 200 dishes run in CI.

## Versioning of This File

Own, semantic version `MAJOR.MINOR.PATCH`, independent of the `CLAUDE.md` bundle version and of README gate version (`docs/15_README_STRATEGY.md`) — README versions the product outward, this file versions itself inward:

| Bump | Trigger | Example |
|---|---|---|
| **MAJOR** | Gate passed / stage transition / architecture decision (E-Nr) flipped | G0 passed → stage 1 begins |
| **MINOR** | Decision made (D-Nr answered), new work package result changes "What's next" | D1 vendor chosen |
| **PATCH** | pure status housekeeping: task check, new assumption, new/resolved blocker | T-0.1 to done |

**Auto-update:** `python scripts/status_bump.py <patch|minor|major> "<one-line change>"` sets date, version, and changelog line automatically. Called by `/done`, `/task`, `/handover` (see `.claude/commands/`) — by hand only if needed. Extra safety net: CI (`.github/workflows/ci.yml`) fails if `docs/07_WORKPACKAGES.md` changes but `docs/01_STATUS.md` stays unchanged in the same diff.
